# HouseLedger — monthly manager statements, one active mobile session, bottom navigation

## Included changes

**Manager mobile:** New *Reports* bottom tab, a monthly report shortcut on Home, and a *View monthly bill list* action on the Rent and Electricity tabs. The report is scoped to the manager's selected assigned house and billing month. It lists all issued rent and electricity bills, precise billed/collected/remaining totals, status, room/resident details, electricity meter segments, and individual payment/reversal receipts. Search room/resident/mobile, filter type and paid/outstanding status, open bill details, load more (30 per batch), refresh, and export.

**Excel:** The backend exports an actual `.xlsx` workbook with **Summary**, **Rent Bills**, **Electricity Bills**, **Meter Details**, and **Receipts** sheets. It includes all issued bills for the chosen house and month, not merely the latest records from the mobile bootstrap snapshot. Untrusted text is escaped and stored as plain text (not executable Excel formulas). The mobile app downloads using the bearer token and opens the operating system's share/save interface so the manager can save or share the workbook. The backend does not store exported copies on the server.

**Session security:** Every successful mobile login replaces the same account's old mobile token atomically in PostgreSQL. This applies to manager, resident, and mobile admin logins. Manager logins through the existing manager web endpoint use the same session slot. The old device receives 401 on its next authenticated operation; the app checks after returning to foreground and while running (every 60 seconds) and takes the user to sign-in. When offline, it cannot receive a real-time push notification, but its old token cannot access the server. This does not alter existing admin web cookie sessions.

**Bottom navigation:** Manager / resident / admin use one shared navigation bar, with a selected indicator, subtle animation, haptics, accessible labels, compact-phone text scaling, and consistent active colors. Tabs switch with short transitions, and scroll positions can be restored when revisiting previously opened tabs. Manager has a fifth destination, **Reports**.

## Required deployment order (important)

1. **Back up** the live PostgreSQL database and app source.
2. Deploy the new backend source and run `npm ci`, then `npm run db:migrate` **before** serving the new login code. New migration: `007_single_mobile_session.sql`, which keeps only each account's newest previously issued mobile token and adds the unique index.
3. Build and deploy the backend as usual (`npm run build`). On Vercel, use the existing project environment configuration; do not add secrets to the mobile build.
4. From the Flutter project run `flutter pub get` (new packages: `share_plus` and `path_provider`), `flutter analyze`, and `flutter test` before building release artifacts. The provided `pubspec.lock` is from the original archive and must be regenerated by `flutter pub get` with your SDK before release. Launch with the existing environment, e.g. `flutter run --dart-define=HOUSELEDGER_API_BASE_URL=https://housemanager-umber.vercel.app/api/v1`.
5. Verify the roles and session behavior on two actual phones; check Excel saving on Android and iOS using the OS share sheet.

## API endpoints (existing version prefix `/api/v1`)

- `GET /mobile/statements?houseId=<UUID>&month=YYYY-MM` — manager-authenticated JSON.
- `GET /mobile/statements/export?houseId=<UUID>&month=YYYY-MM` — manager-authenticated XLSX binary attachment. No public URLs or tokens in query params.

Both endpoints check the current manager assignment and organization from the bearer token. They include only **ISSUED** bills, exclude VOID bills, and use the recorded amount/paid values (not recalculated historical charges). Payment reversals are shown as negative receipts in Excel, and multiple meter segments are retained in a separate sheet.

## Manual acceptance checklist

- Account A: log in on phone 1, log in on phone 2; phone 1 can no longer call authenticated APIs; repeat for manager and resident.
- Run concurrent login attempts for one account: the last committed token remains usable; earlier ones are rejected.
- Manager with house H1: list and export month M; verify data reconciles against issued bills and that house H2 is refused if unassigned.
- Check fully paid, partial, unpaid, no bills, and reversal receipts. Verify Excel totals, decimal cents, meter changes/multiple segments, and search/status filters.
- On 320dp, 360dp, 430dp, and tablet widths test every navigation destination, back buttons, scroll restoration, and return from app background.
